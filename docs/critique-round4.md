# Independent critique, round 4

This is a source trace against `screenshots/image (10).png`, not a rendered A/B test. `node_modules` is absent, so I could not launch the game, exercise touch targets, run tests, or compare browser screenshots. The supplied reference shows a continuous woodland space with distinct characters, foreground and background depth, and in-world action.

## What improved

- **Clean backup recovery:** The title has an Import control. On an empty device, `importBackup` validates and inserts profiles, selects the first restored explorer, and the UI enters the game (`App.tsx`, `store.ts`, `storage.ts`). A placeholder profile is no longer required.
- **One-item review:** A Journal due-item sets `singleReview`; after its success, Continue returns to the Journal rather than advancing through a chapter (`App.tsx`). The review counter uses the selected challenge's authored position.
- **Home and rewards:** Chapter outro art now derives from the chapter's authored reward. The Bramble token is excluded from Home inventory and placement, and reset returns a selected Bramble to Pip before removing unlocks. Earned-coin items have purchase and placement paths (`App.tsx`, `store.ts`).
- **Word Hunt feedback:** After two errors, the correct scene target gets a dashed halo and star marker. The sign displays the recovered English word and brightens after success; Phaser adds visible ambient sparks and a success flash. DOM buttons own both the artwork and pointer geometry, avoiding the earlier invisible-canvas hit-zone mismatch (`ChallengeView.tsx`, `WordHuntScene.tsx`, `styles.css`).

## Biggest remaining gap

The playable hunt still falls short of the reference's inhabited, explorable scene. All hunts reuse one backdrop, one sign, and three equally prominent objects at fixed positions. The sign changes after success, but Puck, Nettle, Hush, and other speakers are not visible within the encounter; neither target location nor environmental consequence expresses the authored quest. The sign says only the answer ID (for example, `apple`) rather than revealing the story clue `FOLLOW THE BLUE FEATHERS`. A child can tap one of three isolated silhouettes, then Continue; there is little reason to inspect the forest. The next independent piece should be the first signpost encounter: give the apple, fox, Puck, and sign a coherent location in a layered scene, then visibly restore the sign's story text before Continue. Judge its captured output beside image (10) for composition, visual depth, distinct characters, and apparent agency, as well as child comprehension.

## Concrete remaining issues

1. **Replay still presents an earned reward as new.** Entering an already completed chapter sets `review=true`; finishing its replay still reaches `story='outro'`, which always shows the chapter keepsake and a victory presentation. Currency is correctly not duplicated, but the screen implies another keepsake was just won. Reproduce by finishing chapter 1, selecting its node again, replaying six questions, and viewing the outro. Show a revisit-specific conclusion or omit the award panel on review.
2. **Import is not usable at the 20-profile limit.** `storage.import` rejects whenever current row count plus incoming backup count exceeds 20, even if every incoming ID collides with an existing profile. It does preserve the existing data, which is good, but the UI gives only a generic import failure. A parent with 20 sibling profiles cannot inspect or restore a backup until deleting a profile. Decide whether to offer a reviewable replacement/merge or a capacity explanation; do not silently overwrite.
3. **Restoring an ID collision can select the old profile.** If no player is currently selected but local data contains an explorer whose ID matches the backup's first explorer, `storage.import` adds a new `(copy)` ID, while `store.importBackup` then searches by the original backup ID and selects the existing explorer. The import appears to succeed but the restored copy is not opened. Return the imported IDs from storage or let the user select among them.
4. **The home has a keyboard positioning mismatch.** Arrow keys on a placed decoration call `placeDecoration` with the item and new coordinates; this works, but the UI does not describe the arrow-key control and `aria-label` is only the generic item label. Several furniture buttons can therefore share labels, and a keyboard user has no location/selection context. Add a short localized instruction and position-aware accessible name; verify focus remains on the moved item after React rerender.

The highest-priority *functional* follow-up is a real browser pass through title restore, a single Journal review, purchasing/placing/moving a keepsake, and two wrong Word Hunt attempts in both languages. Static inspection confirms the wiring but cannot establish touch geometry, focus behavior, persistence after reload, or a visual win against the reference.
