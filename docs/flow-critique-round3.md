# Flow critique, round 3

Read-only source trace of `src/App.tsx`, `src/ChallengeView.tsx`, `src/WordHuntScene.tsx`, `src/ForestScene.tsx`, `src/store.ts`, `src/model.ts`, `src/content.ts`, and `src/storage.ts`. This is a static walkthrough, not a claim of a browser playtest. Dependencies are absent (`node_modules` does not exist), so tests could not be run here.

## Actual path through a new game

The title button opens creation when there are no profiles (`App.tsx:63-71`). Creation saves a `newProfile` with chapter 0, no completions, two starter decorations, and zero currency (`model.ts:58-65`; `store.ts:65-69`), then opens chapter 1's intro. Explore chooses an uncompleted challenge closest to the corresponding skill's current level (`App.tsx:35-57`). A correct answer records an attempt, then completes and saves the challenge before showing success (`ChallengeView.tsx:28-46`; `store.ts:76-81`). Each first completion adds 20 XP and 8 coins. Finishing all six challenges advances the chapter and grants its decoration (`model.ts:89-109`). Next then opens the chapter outro, and the map enables the next node (`App.tsx:53-57`; `ForestScene.tsx:22`). Reload initializes the selected profile from IndexedDB and returns to the title; continuing opens Adventure rather than the exact unfinished question (`store.ts:57-64`; `App.tsx:63-68`).

## Highest-impact gaps

1. **A backup cannot be restored on a clean device without creating an unwanted new explorer first.** With empty IndexedDB, the title routes Begin to creation, and creation/profiles are the only reachable screens (`App.tsx:63-73`). Import exists only in Settings inside the game (`App.tsx:91-114`), which requires a selected profile. Reproduce by clearing this site's data, opening the title, and trying to restore an exported backup: first create a placeholder explorer, navigate to Settings, and import. The imported explorer is added but the selected explorer remains the placeholder (`store.ts:117-125`), so the apparent success message does not put the child back in the restored adventure. A fresh-device recovery path belongs on the title or profile picker, followed by an explicit profile selection.

2. **Chapter 5's reward screen displays the wrong keepsake, and replay can display an unrelated item.** The outro visual and label derive from `p.inventory.at(-1)` (`App.tsx:81`), not `currentChapter.reward`. On first finishing chapter index 4, `rewardCompletion` appends `moss-habitat` and then `bramble-friend` (`model.ts:98-103`); the outro therefore illustrates Bramble's inventory marker using the fallback star art and generic chapter reward label. Reproduce by finishing Bramble's chapter and viewing the outro. On any earlier chapter replay, buy a shop item after original completion and replay: the outro now presents that purchase as the chapter reward. This conflicts with the authored chapter rewards (`content.ts:5-11`) and the one-time reward rule.

3. **The review button expands one due discovery into the rest of its chapter.** The Journal shows up to four individually due challenges (`App.tsx:91`). Selecting one sets `review=true`; `nextChallenge` then chooses the next challenge in the chapter's fixed list regardless of its review due date (`App.tsx:39-45`). Reproduce by completing a chapter, waiting for only one item to become due (or making one failed replay attempt), selecting that Journal item, and pressing Continue after success. The child is sent through later questions and the chapter outro. If the selected item is last, Continue jumps directly to the outro. Review success grants no duplicate currency, which is correct, but the flow is a poor match for a short targeted revisit.

4. **The chapter challenge counter becomes inaccurate during review and after some adaptive ordering.** `ChallengeView` receives an index derived solely from the number already completed in the chapter (`App.tsx:76-81`). All replayed questions in a completed chapter therefore display Discovery 6 of 6, even when the player is on its first question. During first play, the adaptive selector can choose authored questions out of order while the counter describes completion count rather than a stable challenge sequence. Reproduce by finishing chapter 1, opening its first node, and starting its first replay question. This is presentation only, but it makes progress hard to understand.

5. **Home treats a companion unlock as a placeable decoration.** Chapter 5 adds `bramble-friend` to the same inventory as room objects (`model.ts:100-103`). Home renders every inventory item as a button to place (`App.tsx:86-91`), while `decorArt` maps unrecognized items to a star (`App.tsx:14`). Reproduce by finishing chapter 5, opening My Home, choosing the Bramble item, and tapping the room. A star decoration is placed. Bramble is already separately offered in My Wordlings (`App.tsx:86`), so this inventory entry needs a distinct type or Home filtering.

## Persistence and backup notes

- Normal answer completion is awaited before the success screen, and storage updates transform the current IndexedDB row inside a transaction (`ChallengeView.tsx:28-46`; `storage.ts:37-46`). This supports resume after reload, although the exact active question/story screen is not restored.
- Import validates the backup and adds profiles in one transaction, copying colliding IDs rather than overwriting progress (`store.ts:117-125`; `storage.ts:49-61`). The success notice does not identify which explorer was imported or copied. A user with a full set of 20 explorers cannot import even a backup of an existing explorer because storage checks current count plus incoming count (`storage.ts:52`), while the store's precheck counts unique IDs and can pass (`store.ts:119-121`).
- The profile schema validates shape and uniqueness, but not whether `chapter` matches `completed` or whether IDs refer to current challenges (`model.ts:17-52`). A structurally valid modified backup can report chapter 6 with no completed challenges, opening all map nodes and showing the ending. Reproduce by editing those two fields in an exported JSON file and importing it. Decide whether future-content compatibility warrants tolerating unknown IDs; at minimum reject internally contradictory current-world progress.

## Gap from the stated product goal

The source provides 36 authored questions across six chapters, a playable forest path, separate skill records, saved progress, a home, local backups, and bilingual support. The design goal calls for a child to complete a saved journey with deliberate mistakes and for a parent to recover progress on another device (`docs/design.md`). The recovery entry problem is the main blocker to that journey. The other findings make completed rewards, reviews, and the home collection misleading. Existing unit tests cover model/storage contracts but do not exercise a clean-device restore, full UI chapter progression, reward rendering, or the Journal-to-review transition. A real browser pass remains necessary, especially with reload, audio unavailable, mobile input, and Hebrew layout.
